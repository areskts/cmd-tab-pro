# 窗口恢复

窗口控制由用户在“Dock 预览”页开启，需要辅助功能权限；未授权时保留原基本唤回。

- AX 窗口查询失败、属性不完整或仅发现无法识别的窗口：状态未知，不发送 reopen。
- 已确认窗口列表为空：请求应用重新打开窗口，内容由应用决定。
- Finder 在 macOS 27 的 AXWindows 中包含桌面 AXScrollArea，该元素不算窗口；增强自动模式下主动 Cmd+Tab 到仅剩桌面的 Finder 可以重新打开窗口。
- 有非最小化窗口：沿用系统激活行为；应用仍隐藏时前置原窗口。
- 所有窗口最小化：按最近聚焦记录恢复一个；没有记录时选择主窗口，再退回应用提供的顺序。
- 部分最小化：保留已最小化窗口的状态。
- 其他 Space 和全屏窗口依然算已有窗口，不因此新建窗口。自动恢复不移动窗口、不强制切换 Space。
- 兼容模式排除 Finder，桌面激活不得新建 Finder 窗口。
- 目标改变、模式改变、暂停或新的输入取消旧请求；后台回调执行前再次校验目标仍是前台。
- 工具主动进行窗口操作前取消旧请求并抑制短时间内重复唤回，避免最小化后立即反弹。

AX 查询和窗口动作使用单独队列，单次消息超时为 150ms。当前前台 App 的窗口聚焦通过 AXObserver 记录；Dock 展示的 App 仅在需要时查询并订阅变化，不轮询全部应用。

`_AXUIElementGetWindow` 为私有 AX 桥接接口，仅用来获得准确的窗口 ID，以便与 ScreenCaptureKit 对应。接口读取失败时不根据猜测生成 ID。签名和 bundle ID 保持不变。

验证：`Tests/Windows/run.sh` 覆盖决策及取消会话；`Tests/Windows/integration.sh` 使用独立测试应用验证真实窗口身份、最小化、隐藏、恢复、关闭、事件订阅和截图。

`Tests/Windows/integration.sh --finder-only` 在 Finder 无普通窗口时验证桌面排除、主动 Cmd+Tab 重开且不重复创建，以及两种模式下桌面激活不误弹；只关闭测试创建的 Finder 窗口。已有 Finder 窗口时跳过该定向验收。
